# Analyzing Melanoma Evolution with CNN Feature Representations

CS 131 (Computer Vision: Foundations and Applications) project. A CNN-based system that
classifies skin lesions as melanoma or benign on the **SIIM-ISIC 2020** dataset, then
analyzes lesion appearance via CNN feature embeddings and Grad-CAM. See
`CS_131_Project_Proposal.pdf` for the full proposal.

## Pipeline

| File | Purpose |
|------|---------|
| `config.py` | Paths and `TrainConfig` hyperparameters |
| `dataset.py` | SIIM-ISIC dataset, transforms, weighted oversampling, train/val split |
| `model.py` | `MelanomaResNet18` — ResNet18 backbone + linear head, with `embed()` and a Grad-CAM target layer |
| `train.py` | Training loop (BCE loss, AdamW, cosine LR), saves best-AUC checkpoint |
| `embeddings.py` | Extract 512-D embeddings; save to `.npz` *(Week 2)* |
| `similarity.py` | t-SNE/PCA projections, cosine-similarity analysis, nearest-neighbor retrieval *(Week 2)* |
| `embedding_eval.py` | Fine-tuned vs ImageNet embedding separability: linear-probe/kNN AUC, precision@k, silhouette *(Week 2)* |
| `cv_oof.py` | 5-fold out-of-fold embedding + score extraction from the fold checkpoints *(CV)* |
| `cv_metrics.py` | Per-fold and mean ± std validation-AUC table and plots *(CV)* |
| `similarity_oof.py` | Linear-probe / kNN / precision@k re-analysis on the 32k OOF embeddings *(CV)* |
| `arch_metrics.py` | Per-architecture per-fold AUC table and comparison figures *(arch)* |
| `report.tex` | LaTeX final report draft |
| `eval_roc.py` | Validation inference for the ROC curve |
| `make_plots.py` | Training-curve and ROC plots (plotnine) |
| `gradcam.py` | Grad-CAM attention overlays *(Week 3)* |
| `train.sbatch` | SLURM submission script (1× GPU) |

### Data

The dataset (`cdeotte/jpeg-melanoma-256x256`, CC0) downloads anonymously — no Kaggle
credentials required:

```bash
.venv/bin/kaggle datasets download cdeotte/jpeg-melanoma-256x256 -p data --unzip
```

This yields `data/train.csv` and `data/train/<image_name>.jpg` as expected by `config.py`.
The training set is **33,126 images** with **584 melanoma cases (1.76% positive)** — the
heavy class imbalance is handled by a `WeightedRandomSampler` (`pos_oversample=20`).

## Training

The project runs on a SLURM cluster (login node has no GPU). Submit with:

```bash
sbatch train.sbatch                                              # full baseline (config defaults)
sbatch train.sbatch --subsample 0.1 --epochs 2 --out artifacts/checkpoints/resnet18_smoke.pt   # quick pipeline check
```

Logs are written to `artifacts/logs/melanoma-<jobid>.out`; the best checkpoint to
`artifacts/checkpoints/resnet18_best.pt`. To run locally without SLURM: `.venv/bin/python train.py`.

### Regularization experiment — dropout + weight decay (job 83458)

To address the overfitting, a second run added **dropout 0.4** before the classifier head
and raised AdamW **weight decay to 1e-3** (vs the baseline's 0.0 / 1e-4), via the new
`--dropout` and `--weight-decay` flags:

```bash
sbatch train.sbatch --dropout 0.4 --weight-decay 1e-3 --out artifacts/checkpoints/resnet18_reg.pt
```

| Model | Dropout | Weight decay | Best val AUC | Best epoch |
|-------|--------:|-------------:|-------------:|-----------:|
| Baseline    | 0.0 | 1e-4 | **0.9044** | 2 |
| Regularized | 0.4 | 1e-3 | 0.8927 | 2 |

![Validation ROC-AUC by epoch — baseline vs regularized](figures/baseline_vs_regularized.png)

**Finding: regularization did not help.** It slightly *lowered* the peak validation AUC
(0.904 → 0.893) and the model still overfits identically (train AUC → 0.999, val AUC peaks
at epoch 2 then declines). The ~0.011 difference is within the noise of a ~88-positive
validation set, so the honest conclusion is "no meaningful improvement." Larger gains here
require a stronger backbone (e.g. EfficientNet) and proper cross-validation (the dataset's
`tfrecord` column provides folds), not heavier regularization of ResNet18.

## Week 2 — Feature embeddings & similarity

Using the trained baseline backbone (`resnet18_best.pt`), I extracted 512-dimensional
embeddings for all 4,969 validation lesions (`embeddings.py`) and analyzed inter-lesion
similarity (`similarity.py`). This tests the project's core hypothesis: do classification
features encode diagnostically meaningful visual similarity between lesions?

![Lesion embeddings (t-SNE)](figures/embedding_tsne.png)

![Cosine similarity by lesion-pair type](figures/similarity_distribution.png)

**Quantitative similarity (cosine, k = 5):**

| Metric | Value |
|--------|------:|
| Base melanoma rate (validation) | 1.8% |
| Precision@5, melanoma queries | 8.9% (**5.0× lift** over base rate) |
| Mean cosine, melanoma ↔ melanoma | 0.52 |
| Mean cosine, benign ↔ benign | 0.67 |
| Mean cosine, melanoma ↔ benign | 0.47 |

**Finding: the hypothesis is partially supported.** Cross-diagnosis (melanoma ↔ benign)
pairs are the *least* similar while within-diagnosis pairs are more similar, and a
melanoma's five nearest neighbors are 5× more likely to be melanoma than chance — so the
features do encode diagnostic structure. But the signal is modest: melanomas do not form a
tight cluster under t-SNE (mean within-class similarity 0.52, below benign's 0.67),
reflecting melanoma's visual heterogeneity and the modest backbone.

![Nearest-neighbor retrieval in embedding space](figures/nearest_neighbors.png)

Qualitatively, nearest neighbors are clearly visually similar (color, texture, hair, scale)
but frequently differ in diagnosis — the embeddings capture *appearance*, and
appearance-similar lesions often straddle the benign/melanoma boundary, which is precisely
what makes melanoma screening hard.

### Is the structure learned, or already in ImageNet features?

To test whether this diagnostic structure comes from melanoma fine-tuning rather than from
generic pretrained features, I re-ran the analysis on embeddings from an **un-fine-tuned
ImageNet ResNet18** (`embeddings.py --imagenet`) and compared the two (`embedding_eval.py`):

| Metric | Fine-tuned | ImageNet |
|--------|-----------:|---------:|
| Linear-probe AUC (5-fold logistic regression on frozen embeddings) | **0.861** | 0.663 |
| kNN AUC (k = 5) | 0.646 | 0.625 |
| Precision@5 melanoma lift | 5.0× | 3.8× |
| Precision@5 melanoma lift, **excluding same-patient neighbors** | 4.9× | 3.6× |
| Silhouette (cosine) | 0.355 | 0.062 |

![Diagnostic separability of embeddings](figures/embedding_probe_comparison.png)

![Lesion embeddings (t-SNE, ImageNet only)](figures/embedding_tsne_imagenet.png)

**Findings:**
1. **Fine-tuning creates the diagnostic structure.** Linear-probe AUC jumps from 0.66
   (ImageNet) to 0.86 (fine-tuned) and the silhouette rises ~6× (0.06 → 0.36). ImageNet
   features are essentially diagnosis-blind — mean cosine similarity is ~0.64 for *every*
   pair type (melanoma↔melanoma, benign↔benign, melanoma↔benign) — whereas fine-tuning
   pushes melanoma away from benign (0.47 vs 0.67 within-benign). This is direct evidence
   for the project's central claim: the classification objective reshapes the feature space
   toward diagnostically meaningful similarity.
2. **The signal is not a same-patient artifact.** Excluding same-patient neighbors barely
   changes the melanoma precision@5 lift (5.0× → 4.9×), so diagnostically matched neighbors
   are retrieved *across* patients, not just from the same skin/camera.
3. **It remains modest in absolute terms** (linear-probe 0.86 < the classifier's own 0.90;
   kNN AUC 0.65), consistent with melanoma's visual heterogeneity and the ResNet18 backbone.

## Week 3 — Grad-CAM attention

`gradcam.py` overlays Grad-CAM heatmaps (gradients at ResNet18's last convolutional block,
`layer4`) on validation melanoma and benign examples.

![Grad-CAM examples](figures/gradcam_examples.png)

**Finding:** for confident predictions the model's attention concentrates on the lesion
itself rather than background skin or acquisition artifacts (rulers, ink, hair) — a positive
sanity check against the shortcut-learning failure mode common in dermoscopy datasets. Some
melanoma examples are under-predicted (low p(mel)), consistent with the 0.90 AUC; even then
Grad-CAM localizes the lesion, suggesting the misses are discrimination errors rather than
attention to the wrong region.

## Cross-validation: rigorous re-evaluation

The earlier results sit on a single 85/15 stratified split, whose validation set holds
only ~88 melanoma cases — so AUC differences below ~0.01 are not interpretable. To address
this I added **5-fold patient-grouped cross-validation** using the dataset's built-in
`tfrecord` chunks (`tfrecord // 3` → 5 folds; `tfrecord = -1` dropped), and ran both
configurations (baseline and regularized) on every fold — 10 training runs total,
parallelized across H100s (~4 min each).

| Model | Fold 0 | Fold 1 | Fold 2 | Fold 3 | Fold 4 | **Mean ± Std** |
|-------|------:|------:|------:|------:|------:|---------------:|
| Baseline    | 0.884 | 0.874 | 0.897 | 0.861 | 0.847 | **0.873 ± 0.019** |
| Regularized | 0.889 | 0.867 | 0.875 | 0.874 | 0.845 | **0.870 ± 0.016** |

![Per-fold best validation ROC-AUC](figures/cv_per_fold_auc.png)
![Cross-validated validation ROC-AUC (mean ± std)](figures/cv_summary_auc.png)

**Findings:**
1. **The single-split 0.904 was the high end of fold variance.** The honest CV estimate is
   **0.873 ± 0.019**, with folds spanning 0.847–0.897 — a 0.05-wide spread that single-split
   results entirely hid. This is a meaningful recalibration.
2. **The regularization "improvement" is definitively within noise.** Mean baseline 0.873
   vs regularized 0.870 (∆ = 0.003) is well under one standard deviation in either run.
   The earlier 0.904 → 0.893 single-split gap was sampling artifact.

### Architecture comparison under the same protocol

To see whether a larger or more modern backbone helps, I ran the same 5-fold CV for
**ResNet50** and **EfficientNet-B0** under the identical training protocol (`--backbone`
flag added to `train.py`; both backbones come from `timm`):

| Architecture | Params | 5-fold val ROC-AUC |
|---|--:|---:|
| ResNet18                  | 11.2M | 0.873 ± 0.019 |
| ResNet18 + dropout/wd     | 11.2M | 0.870 ± 0.016 |
| **ResNet50**              | 23.5M | **0.872 ± 0.0045** |
| **EfficientNet-B0**       |  4.0M | **0.824 ± 0.034** |

![Architecture comparison (mean ± std)](figures/arch_summary_auc.png)
![Per-fold by architecture](figures/arch_per_fold_auc.png)

**Findings:**
1. **ResNet50 matches ResNet18 in mean AUC but at 4× lower variance** (std 0.0045 vs
   0.019). Larger capacity here doesn't shift the mean — it stabilizes across folds.
2. **EfficientNet-B0 underperforms by ~0.05 AUC** under this protocol. EfficientNet was
   designed for 224×224 with its own learning-rate / optimizer / augmentation conventions;
   running it under ResNet18-tuned hyperparameters is not a fair test of its capability.
   The honest takeaway is that **architecture-protocol coupling matters more than
   architecture alone** here — backbone-swapping at fixed hyperparameters is not the path
   to the ~0.94 the SIIM-ISIC 2020 winners reached.

### Leak-free embedding analysis via OOF predictions

With CV in hand, I extracted **out-of-fold embeddings**: each lesion is embedded by the
fold model that did *not* train on it (`cv_oof.py`). This produces 32,692 OOF embeddings
with **581 melanomas** — 6.6× the val-only set, and methodologically clean (no model has
"seen" the lesion it's embedding). Re-running the linear-probe / kNN / retrieval analysis
on this OOF set (`similarity_oof.py`):

| Metric | Val-only (88 mel) | **OOF (581 mel)** |
|--------|-------------:|------------------:|
| Linear-probe AUC (5-fold logistic regression) | 0.861 | **0.830** |
| kNN AUC (k = 5) | 0.646 | **0.675** |
| Precision@5 melanoma lift | 5.0× | **6.93×** |
| Precision@5 lift, excluding same-patient neighbors | 4.9× | **6.57×** |
| Silhouette, cosine (5k subsample) | 0.355 | 0.273 |

![Lesion embeddings (t-SNE, OOF subsample)](figures/embedding_tsne_oof.png)
![Cosine similarity by lesion-pair type (OOF)](figures/similarity_distribution_oof.png)

**Findings:**
1. **The retrieval signal is real and stronger than the val-only estimate suggested.** With
   6.6× more melanomas in the gallery, a melanoma's five nearest neighbors are **~7×** more
   likely to be melanoma than chance — and this holds across patients (6.57× cross-patient).
   The OOF t-SNE also shows a visible melanoma concentration that the val-only projection
   could only hint at.
2. **Melanoma is heterogeneous, but locally diagnostic.** The OOF similarity distributions
   make the structure clearer: benign lesions form a cohesive cluster (peak cosine ~0.72),
   while melanoma is broader and overlaps benign in *global* mean similarity. The retrieval
   metrics still work because *local* neighborhoods are diagnostic — each melanoma sits near
   a few visually similar melanomas of the same subtype, even though "melanoma" as a class
   doesn't form a single tight blob.
3. **A caveat on raw mean cosines.** OOF embeddings come from five different fold models,
   so raw within-/between-class mean cosine values aren't directly comparable to the
   val-only ones (which were single-model). The linear-probe, kNN-AUC, precision@k, and
   silhouette metrics above are unaffected by this — they evaluate each lesion's local
   geometry, which the OOF construction preserves.
